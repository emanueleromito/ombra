# M4: Release preparation

**Goal:** a first public release, 0.1.0: client wheels on PyPI, GPU and CPU Docker images on GHCR, CI on GitHub runners, public docs, security and legal files, and a public repository exported from this one without internal material.

**Starting point:** M3 done (`results/m3-report.md`): the client, local mode with the Python expansion, `langchain-ombra` and the quickstart.

**Order and parallel work:**

```
T4.3 (branches) --> T4.2 (CI) --> T4.1 (wheels) --+
                              \-> T4.4 (images, release) -+--> T4.8 (export)
T4.5 (cleanup) --> T4.6 (public docs) ---------------------+
T4.7 (security, legal) ------------------------------------+
```

T4.3, T4.5 and T4.7 can start at once. T4.1 and T4.4 both edit the workflows from T4.2, so they run one after the other. T4.6 follows T4.5 because both touch the same docs and comments. T4.8 runs last: its leak test needs the cleaned tree.

**Docs style (applies to T4.6 and every README):** write like a person explaining to a colleague: plain words, short sentences, active voice, concrete numbers instead of adjectives. No em or en dashes as punctuation. No filler or marketing words ("seamlessly", "robust", "leverage", "cutting-edge", "delve", "unlock", "empower", "it's worth noting", "in today's world", "not just X, but Y"). No emoji. A short paragraph instead of headings or bullets where it reads better. Say plainly what is not supported and what is slow. Mermaid diagrams for architecture, request flow and the threat model; benchmark charts generated by a script from the results data and committed as SVG next to it; one sentence per figure on what to take from it. Reread every page before finishing and cut whatever sounds generated (repeated sentence shapes, empty summaries, hedging).

### T4.1 Client wheels with the exact local expansion

**Why:** local mode (T3.7) expands queries in Python with one extra level and about 5x the server's time (option A of decision 0022, measured too slow); M3 compiles the exact expansion for Linux x86_64 and Python 3.12 only.
**Depends on:** T4.2
**Steps:** build the `ombra` client wheels with cibuildwheel for Linux x86_64 and aarch64 and macOS (arm64, x86_64), Python 3.11 to 3.13, with OpenFHE 1.6.1 and the C++ OpenFHE CPU expansion (the server's exact tree method, `core/`) compiled in; local mode uses it instead of the Python expansion; relax `requires-python` to `>=3.11`; CI builds and tests every wheel.
**Done when:** each wheel installs on its platform and Python version without a compiler, the local-server parity test (T3.7) passes with the compiled expansion, local mode uses the same number of levels as the server, and query time at d = 768 is measured and recorded in `results/`.
**Status:** todo

### T4.2 CI on GitHub runners

**Why:** every PR should be checked without Modal, so CI costs nothing per PR and does not need Modal tokens.
**Depends on:** T4.3
**Steps:** a Docker image with OpenFHE 1.6.1 and the build tools, built by a workflow and pushed to GHCR, rebuilt only when its Dockerfile changes; a PR workflow that runs `make lint`, the C++ CPU build, `make test` and the `openfhe` tests inside that image; GPU tests (`make test-gpu`) on Modal only by manual dispatch or a nightly schedule, with the Modal tokens as repository secrets.
**Done when:** a PR to `dev` runs lint, C++ CPU build, CPU tests and `openfhe` tests on GitHub runners and blocks merge on failure; a PR run reuses the cached image (no OpenFHE build) and takes under 15 minutes; the GPU workflow runs on manual dispatch and on schedule, never on PRs.
**Status:** todo

### T4.3 Branches

**Why:** `main` should only move at releases, so day-to-day merges need their own branch.
**Depends on:** none
**Steps:** create `dev` from `main`; make `dev` the default branch for PRs and protect both (PR required, CI required once T4.2 lands); `main` takes only release merges from `dev`; delete merged remote branches; enable automatic deletion of head branches; update the PR target in `CLAUDE.md`.
**Done when:** `dev` exists and is the default branch, both branches are protected, no merged branch remains on the remote, auto-delete is on, and `CLAUDE.md` says PRs target `dev`.
**Status:** todo

### T4.4 Docker images, compose and release workflow

**Why:** users run the server from an image, and a release should be one tag push.
**Depends on:** T4.2, T4.1
**Steps:** a GPU server image (CUDA runtime, `sm_80` and `sm_86`) and a CPU image (local and test use); a `docker-compose.yml` that starts the server with a persistent volume; a release workflow on `v*` tags that builds and pushes both images to GHCR and publishes the wheels (T4.1) and `langchain-ombra` to PyPI through trusted publishing (no API token); set version 0.1.0 in every package and the server; start `CHANGELOG.md`.
**Done when:** `docker compose up` starts a server that the quickstart client can search against; a tag pushed on a test repository or a dry run publishes images to GHCR and wheels to TestPyPI; all versions read 0.1.0 and `CHANGELOG.md` has a 0.1.0 entry.
**Status:** todo

### T4.5 Code cleanup

**Why:** task IDs, milestone names and internal rule numbers mean nothing to outside readers.
**Depends on:** none
**Steps:** remove task IDs (`T1.4`), milestone names (`M2`) and references to "hard rule N" and to `CLAUDE.md` from code, comments, tests, test names, markers, error messages, file names and benchmark flags; where a reference explains why the code does something, replace it with the reason in plain words (for example "the server never receives the secret key" instead of "hard rule 2"); rename files, functions and flags by what they do. `docs/plan/` and `docs/decisions/` keep their IDs.
**Done when:** a grep for task IDs, milestone names, "hard rule" and `CLAUDE.md` outside `CLAUDE.md`, `.claude/`, `docs/plan/` and `docs/decisions/` finds nothing; `make test`, `make lint`, `make test-openfhe` and `make test-gpu` pass.
**Status:** todo

### T4.6 Public docs

**Why:** a user decides from the README and the security page whether to trust the project.
**Depends on:** T4.5
**Steps:** add the "Docs style" rules above to `CLAUDE.md`; write the README, quickstart (update), architecture overview, threat model and security page, limitations page, one benchmark page with its reproduction scripts and SVG charts, and `examples/`; add a "Security invariants" section to `CONTRIBUTING.md` stating, as project rules, the 128-bit minimum, the secret key only on the client, every GPU kernel tested for exact agreement with OpenFHE, no plaintext in logs and versioned file formats.
**Done when:** every page follows the docs style (no dashes as punctuation and none of the listed words, checked by a CPU test over the public docs); the architecture, request flow and threat model have Mermaid diagrams; each benchmark chart is regenerated by its script from `results/` data; every example runs in CI; `CLAUDE.md` has the "Docs style" section and `CONTRIBUTING.md` the "Security invariants" section.
**Status:** todo

### T4.7 Security and legal

**Why:** a public crypto project needs a way to report vulnerabilities, clean history and clear licensing.
**Depends on:** none
**Steps:** `SECURITY.md` with a reporting address and response times; Dependabot for pip, GitHub Actions and Docker; enable secret scanning and push protection; run gitleaks over the full history and fix or document every hit; `NOTICE` listing third-party licenses (OpenFHE, faiss, gRPC and the rest of the shipped dependencies); CLA Assistant on PRs; triage the low-severity findings from the M1 to M3 reviews (fix, or record why not).
**Done when:** `SECURITY.md`, `NOTICE` and the Dependabot config are merged; secret scanning is on; the gitleaks report over the full history has no unresolved hit; CLA Assistant comments on a test PR; every low-severity finding has a recorded outcome.
**Status:** todo

### T4.8 Export script for the public repository

**Why:** the public repository must not carry internal plans, decisions, agent files or results.
**Depends on:** T4.4, T4.5, T4.6, T4.7
**Steps:** a script that builds the public repository from an allowlist of paths; it excludes `CLAUDE.md` (every one), `.claude/`, `docs/plan/`, `docs/decisions/` and internal results, strips links to them from the files it keeps, and creates a fresh history with one commit per release; a test that runs the export and fails if any excluded path, a task ID, a milestone name or "hard rule" appears in the output.
**Done when:** the export of the current tree passes the leak test, builds, and passes `make test` on its own; a planted excluded file or task ID makes the test fail.
**Status:** todo
