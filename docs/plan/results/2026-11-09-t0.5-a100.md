# T0.5: GPU query expansion on A100

- **Commands:** `make bench TASK=t0.5` then `make results-pull` (timings); `modal run modal_app.py::test_gpu --pytest-args "--expansion-large -k test_gpu_query_expansion"` (exact oracle at the same sizes, on A10)
- **Commit:** `5949a20`
- **GPU:** NVIDIA A100-SXM4-40GB (timings); NVIDIA A10 (oracle). The kernels are integer-only, so results do not depend on the GPU model, but the exact comparison itself ran on the A10.
- **CUDA:** 12.6.3 image, nvcc 12.6.85. Compiled for sm_80 and sm_86.
- **OpenFHE:** v1.6.1, openfhe-python 1.6.1.0 (pinned image)
- **Parameter set:** `m0_depth2` from `core/params/ckks_presets.json`, unchanged: HEStd_128_classic, ring dimension 16384, depth 2, scaling 50 bits, first modulus 60 bits, batch size 8192, FIXEDMANUAL, HYBRID (decision 0009). 3 Q towers, 2 P towers, 2 key-switch digits.
- **Raw output:** `docs/plan/results/raw/results/t0.5-a100.json` (gitignored)

## Oracle against OpenFHE (A10)

`ombra_expand_gpu` runs the OpenFHE CPU tree and the GPU tree on the same inputs. Every stage (NTT, digits, inner product with the permutation, ModDown, one automorphism per Galois element) and every leaf must match exactly: all RNS words, moduli, level, noise-scale degree and scaling factor. 5 of 5 passed, with no mismatch at any size.

| d | L | Exact RNS match | Max decrypted leaf error (GPU) | CPU tree (s) | GPU tree (s, Debug build) |
| --- | --- | --- | --- | --- | --- |
| 13 | 5 | PASS | 1.448e-09 | 0.267 | 0.0051 |
| 16 | 5 | PASS | 1.552e-09 | 0.309 | 0.0056 |
| 384 | 10 | PASS | 1.071e-08 | 8.980 | 0.1627 |
| 768 | 11 | PASS | 1.903e-08 | 17.640 | 0.3267 |
| 1536 | 12 | PASS | 2.910e-08 | 35.700 | 0.6570 |

The test's decrypted GPU-vs-CPU difference (up to 4.128e-08) is not a GPU error. The two ciphertexts are identical word for word; each `Decrypt` adds fresh random noise in `CKKSPackedEncoding::Decode` (`ckkspackedencoding.cpp:455-460`), so two decryptions differ.

CPU errors and CPU timings are in `2026-11-09-t0.5-cpu.md`.
