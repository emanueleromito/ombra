# T2.2: end-to-end latency of `m0_compact_n8192` against `m0_depth2`

- **Command:** `modal run modal_app.py::bench --task t1.3 --extra "--presets-t13 m0_depth2,m0_compact_n8192"`, then `make results-pull`. Both presets ran in the same Modal container, one after the other.
- **Commit:** `5f95b1b` (branch `task/m2-batch-a` plus T2.2's harness change: the T1.3 harness now takes a preset, `--presets-t13`, and records the host CPU). It includes T1.4's kernels and T2.1.
- **GPU:** NVIDIA A100-SXM4-40GB. **CUDA:** 12.6.3 image. **OpenFHE:** v1.6.1, openfhe-python 1.6.1.0 (pinned image).
- **Host CPU:** Modal hides the model: `/proc/cpuinfo` has no model name (recorded as "unknown"). The container sees 17 usable cores (`os.cpu_count()` = 17, scheduler affinity = 17).
- **Presets:** both from `core/params/ckks_presets.json`, unchanged. `m0_depth2` has 8192 slots per ciphertext, `m0_compact_n8192` 4096 (ring 8192, batch size 4096), so the compact preset needs about twice as many blocks for the same vectors.
- **Method:** as in `2026-11-09-t1.3-a100.md`: 20 timed queries per case after 3 warm-ups, median per step, Release build, network excluded, 12 cases per preset (d = 384, 768, 1536; 100k and 1M vectors; 5% and 20% searched). Total = sum of per-step medians; "server" = the non-client steps.
- **Raw output:** `docs/plan/results/raw/results/t2.2-m0_depth2-a100.json` and `t2.2-m0_compact_n8192-a100.json` (gitignored).

## Conclusion

**End-to-end latency of the compact preset is 0.52x to 0.65x that of `m0_depth2` in all 12 cases** (1.5x to 1.9x faster), on the same machine in the same run. The server part alone is 0.53x to 0.65x. Every step that costs real time is faster, including the client's:

- Expansion: 0.47x to 0.57x (72.97 ms to 34.59 ms at d = 1536, 100k, 5%).
- Client encode and encrypt: about 0.50x. Reading the query on the server: 0.30x. The query is half as big (394,207 bytes up against 787,423).
- Client stage 2 (decrypt, top-k): 0.66x to 0.68x, although the compact preset has about twice as many result ciphertexts (49 against 25 blocks in the largest case). Each ring-8192 ciphertext decrypts faster than the count ratio costs. This differs from the recall driver's 1.39x to 1.49x slower decryption noted in decision 0013, which scans every block and measures something else.
- Stage 2 GPU: 0.98x to 1.35x. Equal at many blocks, slower at one or two blocks. It is 2% to 8% of the total, so it does not move the result.

The gain is smallest where client decryption dominates (1M vectors, 20% searched: 0.64x to 0.65x) and largest at small searches (0.52x to 0.54x).

**Recall rule (decision 0012):** data exist. `2026-11-09-t1.7-compact-recall.md` shows the compact preset passing on 3 datasets (d = 384, 768, 1536), 1,000 queries each, 22 settings each, worst gap 0.0004 against a tolerance of 0.005. No new recall run was needed.

**Verdict:** accepted as "fast" (decision 0013): latency clearly lower and the recall rule passes.

## Limits

- One run on one machine. The host was slower than in the T1.3 file: `m0_depth2` totals are 1.1x to 1.7x those of `2026-11-09-t1.3-a100.md` (client stage 2 at d = 1536, 1M, 20%: about 260 ms against 135 ms). The CPU model is hidden, so this cannot be tied to a CPU. Both presets ran on the same host, so the ratios are comparable, but absolute figures are not comparable with other files. The M1 refresh file saw the same kind of variation.
- Network time excluded. The compact query is half the bytes, which would help more over a real network.
- Stored blocks other than block 0 are device copies of block 0, and score error is checked on block 0 and the last masked block only (as in T1.3).
- Score error of the compact preset is 3.7e-06 to 9.0e-06 here, 300x to 600x that of `m0_depth2`. T1.7's recall run found no effect on recall, but users who rely on score values get less precision.
- Storage per vector does not improve (decision 0013): "fast" means faster queries and smaller keys, not cheaper storage. The compact preset needs about twice as many ciphertexts, and the 1M, 20% case has 49 blocks resident.
- Recall datasets are English text embeddings at 100,000 vectors.
