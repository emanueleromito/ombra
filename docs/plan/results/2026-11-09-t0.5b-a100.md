# T0.5b: faster query expansion

- **Commands:** `make bench TASK=t0.5` then `make results-pull` (A100 timings); `modal run modal_app.py::test_gpu --pytest-args "--expansion-large -k test_gpu_query_expansion"` (exact oracle, A10); `modal run modal_app.py::profile_expand --dims 384,768,1536` (stage profile, A10)
- **Commit:** `f6268fd`
- **GPU:** NVIDIA A100-SXM4-40GB (timings); NVIDIA A10 (oracle and profile). The kernels are integer-only, so results do not depend on the GPU model, but the exact comparison itself ran on the A10.
- **CUDA:** 12.6.3 image. Compiled for sm_80 and sm_86.
- **OpenFHE:** v1.6.1, openfhe-python 1.6.1.0 (pinned image)
- **Parameter set:** `m0_depth2` from `core/params/ckks_presets.json`, unchanged: HEStd_128_classic, ring dimension 16384, depth 2, scaling 50 bits, first modulus 60 bits, batch size 8192, FIXEDMANUAL, HYBRID (decision 0009). 3 Q towers, 2 P towers, 2 key-switch digits.
- **Raw output:** `docs/plan/results/raw/results/t0.5-a100.json` (gitignored)

## What changed

- All splits of a tree level run in one batched launch, in chunks.
- Basis conversions run while the forward NTT loads its input. The combine is the end of the last forward NTT.
- The NTT is two kernels (a strided pass and a shared-memory pass) instead of several global passes. Twiddles use Shoup multiplication.

## Oracle against OpenFHE (A10)

One split on its own takes 136 to 142 us end to end, against 41.6 to 42.0 us per split when batched. Host enqueue falls from 23.2 us to 0.23 us per split; an empty kernel launch costs about 2 us.
