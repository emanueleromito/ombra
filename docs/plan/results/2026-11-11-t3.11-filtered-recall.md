# T3.11: filtered recall@10 on two real datasets (decisions 0019 and 0012)

- **Command:** `modal run modal_app.py::filtered_recall` (A100-40GB, preset `fast` = `m0_compact_n8192`). Code: `core/bench/filtered_recall.py`. Raw JSON: `2026-11-11-t3.11-filtered-recall.json` (this folder).
- **Path:** `ombra.collection.Collection.create` + `Collection.search` (`run_search`) against the real `ombra_server`. Probe rule of 0019: first round = unfiltered probe count ceil(sqrt(clusters)), widen 2x only below k matches, up to 8x, then the Strict fallback (on). Re-ranking at 3 x k (client default). k = 10, 1,000 queries per cell.
- **Datasets** (real text, real categorical attributes, licence allows benchmark use; data downloaded at run time, never committed; embeddings computed with `sentence-transformers/all-MiniLM-L6-v2`, Apache-2.0, d = 384):
  - **arXiv abstracts** (`gfissore/arxiv-abstracts-2021`, CC0-1.0): 40,000 abstracts (every 48th row), 20 clusters, first round 5. Fields: primary category (top 63 + other, 64 values), submission year in 2-year bins (16 values). Chosen: the one public text corpus with a rich real category and a date, under CC0.
  - **banking77** (`PolyAI/banking77`, CC-BY-4.0): 10,003 train utterances as database, 1,000 random test utterances as queries (a real split), 6 clusters, first round 3. Field: the intent (77 values hashed to 64 buckets, `intent % 64`; ground truth uses the same buckets). Chosen: natural about 1.3% categories and strongly topical.
- **Ground truth:** brute-force exact filtered top-10 in numpy (float64) over the matching vectors. **Plaintext baseline:** the same pruning (the clusters the encrypted run probed) with exact scores, so pruning loss and CKKS loss can be told apart.
- **Filters:** value sets (OR inside one field) built greedily to about 1%, 10%, 50% of the vectors, in two orders: "clustered" (values sitting in few clusters first) and "spread". `eff` = effective number of clusters the matches occupy (exp of entropy; 1 = one cluster, 20 or 6 = uniform). Queries are random, not matched to the filter.
- Balanced preset not run (cost).

## Verdict

**Decision 0012 (encrypted recall within 0.005 of plaintext at the same cluster settings): holds.** In all 21 cells (2 datasets, 1,000 queries each, filtered and unfiltered) the encrypted recall equals the plaintext recall under the same pruning exactly (gap +0.0000, worst single query 0.00). CKKS noise and the filter columns cost no recall on real data. Caveats: preset `fast` only; 384 dimensions only; the plaintext baseline reuses the clusters the encrypted run chose, so a different cluster choice caused by noise would not show (centre scores are noisy at about 1e-5, far below typical score gaps).

**Decision 0019 recall condition (filtered recall@10 about 1.000, except correlated 50% at about 0.95): does NOT hold on real data.** Unfiltered recall at the first-round probe count is 0.983 (arXiv) and 0.993 (banking77); filtered recall falls below it as the filter gets more selective:
- 1% filters: 0.76 to 0.81 on arXiv (3 of 4 cells), 0.76 on banking77 for a spread filter; only the one-cluster banking77 filter (eff 1.0) reaches 1.000.
- 10% filters: 0.89 to 0.97 on arXiv, 0.91 to 0.93 on banking77.
- 50% filters: 0.97 to 0.98 on both, near the unfiltered value.
The loss is pruning, not encryption (plaintext under the same pruning is identical). The cause is the stopping rule: the loop stops as soon as k matches are found in the first 5 (or 3) clusters, but those k matches are not the best k among all matches, which sit in clusters never probed. The extra-round rule almost never fires (mean 0.00 to 0.03 extra rounds in most cells, no Strict fallback, no incomplete answer in any cell), because a 10% to 50% filter always leaves 10 matches in the probed clusters. The synthetic result (1.000) came from well-separated clusters; real text clusters are blurry and the true neighbours of a query spread over more clusters.

The cost of fixing it is probe count, which is what 0019 recorded as the client policy: a minimum number of clusters, or continuing past k matches. Not measured here; a follow-up should sweep n_probe (for filtered queries) against recall on these two datasets. Extra rounds: only the 1% clustered filter on arXiv used them (mean 1.04, max 2; 13.9 clusters searched on average) and banking77 clustered 1% (mean 0.34, max 1).

## Limits and notes

- One embedding model, d = 384, `fast` preset, 10k and 40k vectors (not 100k); two collections of 6 and 20 clusters.
- Queries are not related to the filter. Filters tied to the query (a user searching within the category they mean) would lose less.
- Found while running: `Collection.create` fails with `Encode(): Scaling factor too small` when k-means centers contain denormal-sized entries (about 1e-40, from faiss float32). The script flushes entries below 1e-9 in centers and vectors before create (as `core/bench/recall.py` already does, FLUSH = 1e-9). The client should do the same in `ombra/collection.py` or `clustering.py`; not changed here (out of scope).
- 1,000 queries per cell: recall standard error is about 0.005 or smaller per cell.
