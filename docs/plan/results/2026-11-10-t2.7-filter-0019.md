## Method

**Part 1, score error with filter columns.** d = 384, one block of `slots` unit-norm random vectors (8192 at `m0_depth2`, 4096 at compact), filter fields of cardinality 4, F = 0, 1, 4 and F_max. F_max is found by asking the server for the largest F that `CreateCollection` accepts, and compared with the formula in `server/search/src/layout.cpp`. Per vector the number c of matching fields is drawn uniformly from 0..F (exactly c fields are set to the wanted value, the others to a random other value), so every class has vectors and about `slots / (F + 1)` vectors match all fields. The query asks for value 0 on every field. 3 queries. Reported: max |decoded score - numpy score| over the vectors matching every field and over all vectors; the smallest distance of a decoded slot to a decoder boundary (4m - 2); the smallest observed gap between the highest slot of class c and the lowest of class c + 1 (expected lambda - 2 = 2 minus twice the error); count of vectors with a wrong c; ratio to the F = 0 error against the estimate sqrt(1 + 16 F). With |score| <= 1 the distance to a boundary is at least lambda / 2 - 1 = 1.

**Part 2, the decision-0012 rule.** Same method as T1.6/T1.7 (`core/bench/recall.py`, rule in `core/bench/recall_check.py`): recall@10 of the encrypted pipeline without re-ranking against the plaintext recall of the same cluster setting (exact centers, exact scores), the gap must stay within 0.005 at every setting, at least 1,000 queries. Differences from T1.7: one synthetic dataset (Gaussian mixture, 16,000 unit vectors, d = 128, 8 components), clustered into 8 blocks by faiss spherical k-means (so nlist = 8 and nprobe 1, 2, 4, 8, where nprobe = 8 is the full scan); two filter fields of 8 values (D = 144 query entries); the truth is the exact top-10 over the vectors that match the filter. As in `recall.py`, one encrypted scan of all clusters per query, restricted to the probed clusters afterwards (probed clusters chosen by the decrypted stage-1 scores). Two variants: `no_filter` (all-ones on both fields) and `filter` (one value per field, about 1/64 of the vectors match). The same GPU path, band decode and server as in part 1.

**Part 3, filtered recall with the selective-filter loop (decision 0019).** Same 16,000 vectors in 8 k-means clusters (about 2,000 each), 50 queries from the same mixture, k = 10, initial nprobe p = 2. Six filter fields of 2 values, one per (selectivity, placement); value 0 is the filter value, the query is free (all-lambda) on the other five fields. Selectivity 1% (160 vectors), 10% (1,600), 50% (8,000). Placement `independent`: vectors chosen at random; `correlated`: the matching vectors fill whole clusters in a random order (so a 1% filter lives inside one cluster). Loop: round 1 = the p best clusters by decrypted stage-1 score; after each round count vectors with c = F (all fields match); stop at k; otherwise the next round has twice as many clusters as the last, up to max_probe = mult x p clusters in total; then Strict fallback (every remaining cluster); else `incomplete`. mult = 8 is the decision's default (max_probe = 16 exceeds the 8 clusters, so the schedule alone reaches all clusters and Strict is never a separate step); mult = 2 (max_probe = 4) is added so the fallback is exercised. Recall@10 against the brute-force top-10 over all matching vectors. Latency is the wall time per query as seen by the client (encrypt query, gRPC to the local server, GPU search, client decrypt and decode), 3 untimed warm-up queries per filter; it is not a server latency.

## Limits

- One synthetic dataset, 16,000 vectors, d = 128 for parts 2 and 3; d = 384 for part 1. Not text embeddings; the 0012 rule asks for two real datasets, so a pass here is not the T1.6 acceptance.
- Part 1 uses 3 queries per F; the maxima are over 3 x `slots` values.
- With 8 clusters, a Strict fallback and "all clusters" are the same thing at mult = 8.
- Latency includes client-side Python decrypt and localhost gRPC; it is not comparable to the server-only numbers of T1.3/T2.2.
