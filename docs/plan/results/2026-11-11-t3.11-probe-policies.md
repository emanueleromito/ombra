# T3.11 follow-up: probe policies for filtered search (plaintext simulation)

**Updated 2026-11-11 (decision: drop check A).** The shipped policy is now "E2" (E plus one capped widening round, fixed 2 rounds). The earlier E and E+A rows and the radius sweep below are superseded: check A never pruned, so the radii were removed from the stats (blob version 3).

- **What:** `core/bench/filter_probe_sim.py` (CPU only, numpy + faiss; no Modal, no encryption). JSON: `2026-11-11-t3.11-probe-policies.json`. Embeddings `sentence-transformers/all-MiniLM-L6-v2` on CPU, same loaders, cluster counts (arXiv 40,000 vectors / 20 clusters; banking77 10,003 / 6), queries (1,000 per cell) and filter cells as `2026-11-11-t3.11-filtered-recall.md`. Data fetched from the public URLs into a gitignored cache, never committed.
- **Why a simulation is valid:** T3.11 measured encrypted recall equal to plaintext recall under the same cluster choices (gap +0.0000 in all 21 cells). Here exact plaintext scores are used with the same planner code the client runs (`client/ombra/probe.py`). Check: policy A0 (decision 0019 as run in T3.11, stop at k matches) reproduces T3.11's recall in every cell (e.g. arXiv primary_category clustered 1%: 0.795; banking77 spread 1%: 0.755).
- **Ground truth:** brute-force exact filtered top-10 (float64). k = 10. A0 and B (baselines) fall back to a full scan below k matches; E2 has no fallback (fixed round count, `incomplete` instead).
- **Policies** (floor for all: ceil(sqrt(clusters)) clusters = 5 for arXiv, 3 for banking77):
  - **E2 (Fast)**: round 1 = E: clusters in centre-score order, zero expected matches skipped, add until the expected matches reach 3k, never fewer than the floor. Round 2 = always exactly one widening round: the next clusters with nonzero expected matches, 2x round 1's real clusters, capped by what is left. Expected selectivity below 0.5%: scan all clusters in two rounds. Every filtered query does exactly 2 rounds.
  - **E2 (Decoy)**: the same with round 1's real clusters capped at 2 x floor, and padded with random decoys so Decoy requests min(C, 2f) clusters in round 1 and min(C - 2f, 4f) in round 2 (f = floor), independent of the filter. "Clusters" for Decoy counts the requested clusters (decoys included); decoy results are valid candidates.
  - **Strict**: all clusters in two rounds (halves by cluster id): recall is exact by construction, not simulated.
  - **B**: baseline, decision 0019's rule stopping at 3k matches.
  - **A0**: baseline, decision 0019 unchanged (stop at k).
  Unfiltered queries in the E2 rows use the Decoy/Strict rule (round 1 = floor, round 2 = next 2 x floor), so they also do 2 rounds; A0 and B unfiltered stay at 1.
- **Modelled latency (not measured):** `latency = 71 ms + 10.8 ms x clusters searched + 0 ms x extra rounds`, a least-squares fit over the 20 cells of T3.11's measured mean latencies (RMSE 18 ms); the per-round term came out negative (clusters and rounds are correlated in T3.11's data) and was dropped to 0, so rounds are free in this model and the real cost of extra rounds is understated. A full scan is priced as all clusters. Treat the numbers as orders of magnitude.
- **Target:** recall@10 >= 0.95 at about 1% selectivity.

Reading:
- **The radius quantile has no measurable effect** (identical numbers for 1.0, 0.99, 0.95, 0.90, 0.75). Member-to-centre cosines in these 384-d text clusters are low (the clusters are blurry), so `theta_qc - theta_r` is near or below zero for nearly every cluster whatever the quantile, the bound is about 1, and check A almost never prunes a cluster. The result is driven by `max_rounds`, not by the radius.
- Every setting meets the target: min recall at ~1% is 0.991 (2 rounds) or 1.000 (3 or 4 rounds), and no filtered cell is below the unfiltered recall minus 0.01 (the worst is +0.007 above it).
- **Chosen default (cheapest that meets both criteria): quantile 1.0 (the exact max-radius bound, so no heuristic) with `max_rounds = 2`**: min recall 0.991 at ~1%, 9.8 clusters on average at ~1% and 11.2 over all filtered cells. 3 and 4 rounds add about 1.4 to 2.6 clusters for +0.009 recall. A quantile below 1.0 would only be justified if it saved clusters, which it does not here, so it is not used (the stats blob stores `cos_bound` next to `cos_min`, so a quantile can be chosen later without a format change).
- Caveat stated plainly: this is a cost win only against 4 rounds. Against a full scan, check A saves little on this data; the gain over the 0019 rule comes from the first-round size (3k expected matches, empty clusters skipped) and the extra round(s), not from the bound. Data with tighter clusters (smaller `theta_r`) would benefit from A; not tested.
