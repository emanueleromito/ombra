# T1.3: end-to-end query latency

- **Command:** `make bench TASK=t1.3` then `make results-pull`
- **Commit:** `7be45e4`
- **GPU:** NVIDIA A100-SXM4-40GB (pinned with `gpu="A100-40GB"`)
- **CUDA:** 12.6.3 image. Compiled for sm_80 and sm_86.
- **OpenFHE:** v1.6.1, openfhe-python 1.6.1.0 (pinned image)
- **Parameter set:** `m0_depth2` from `core/params/ckks_presets.json`, unchanged (decision 0009)
- **Timing:** 20 timed queries per case after 3 warm-up, median per step, Release build. Network time excluded; bytes each way are reported. Search kernels are the T0.4 ones, before any T1.4 optimization.
- **Raw output:** `docs/plan/results/raw/results/t1.3-a100.json` (gitignored)

## Method

One real query path: the Python client holds the secret key, and a separate C++ server process sees only the context, public evaluation keys and ciphertexts. Expansion leaves reach both searches device to device. Stage 1 scores the encrypted query against encrypted cluster centers; the client decrypts and picks clusters; stage 2 searches the chosen clusters on the GPU (multiply-and-add, relinearize, rescale, encrypted mask, rescale); the client decrypts and takes top-k.

centers block and stored block 0 are real encrypted random unit vectors; the other chosen blocks are device-to-device copies of block 0 (kernel timing does not depend on the values); network time excluded. The client decrypts one real result ciphertext per chosen block.

Chosen clusters are assumed packed contiguously, into ceil(fraction x N / 8192) blocks. With nlist = 100 at 100k and 1000 at 1M, nprobe = fraction x nlist. Real clusters straddling block boundaries touch up to one extra block per chosen cluster.

Only the centers, chosen blocks and working buffers are on the device. Copying the chosen blocks from host to device is a stand-in for M2 cluster paging, reported apart and not part of the latency.

## Key findings

- **A full encrypted query takes 48 to 290 ms** on one A100, at 100,000 to 1,000,000 vectors, d = 384 to 1536 (single query stream, excluding network). That is 3.4 to 21 queries per second with the client's work included, and 7.2 to 35 per second counting only the server.
- **Expansion dominates small searches:** 63% of the query at d = 1536, 100k, 5% (71.9 ms). Stage 2's GPU work is small until many blocks are searched (47.3 ms at d = 1536, 1M, 20%).
- **Client decryption dominates large searches:** 134.8 ms, 46% of the query, at d = 1536, 1M, 20%, because the client decrypts one ciphertext per chosen block.
- **Leaf handoff costs 12.4 ms at d = 1536** (copying the 1536 leaves into the search's query buffer on the device). It could be removed by pointing the search at the leaf buffers.
- **Score error stays well inside the bound** (at most 1.7e-08), and each query's bytes are small: 787 KB up, and 526 KB to 6.8 MB down.
- All cases fit on the device in one pass, including 25 blocks (30.2 GB) at d = 1536. Paging chosen clusters from the host would add up to about 2.3 s for that case with `cudaMemcpy` from pageable memory, so caching clusters on the GPU matters; that is M2.
