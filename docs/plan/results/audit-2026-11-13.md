# Security audit before the public release (2026-11-13)

- **Tree audited:** `dev` at `7d83b19` (337 tracked files, 346 commits over all refs).
- **Method:** static review, read only. One subagent per area produced raw findings; the main session opened the cited lines for every high finding and for most medium ones, dropped false positives, merged duplicates and set the severity. No code was changed.
- **Not done:** no Modal or GPU run, so nothing under `tests/test_gpu_*` was executed. gitleaks is not installed here and could not be downloaded, so the history scan used pattern searches over `git log --all -p` (see "Coverage"). `clang-format` is not installed, so the C++ half of `make lint` did not run.

## Summary

No critical finding. The cryptographic core holds: every shipped preset is above the 128-bit floor and the floor is enforced on every C++ path, the server has no code path for a secret key, every CUDA kernel has an OpenFHE oracle test that compares RNS words and metadata, and all formats carry a checked version header. No secret was found in the tree or in the history.

There are 9 high findings. They fall into four groups:

1. **The client writes the secret key to a temporary file in plaintext** on every collection create and open (A-01).
2. **The server can be exhausted cheaply:** by anyone who completes a TLS handshake (A-03) and by any holder of a read key (A-02).
3. **The Decoy and Strict levels do not hide what the documents say they hide,** because the client fetches the top candidates by ID after every search (A-04).
4. **The tree is not ready to publish:** the licence texts carry a contact placeholder (A-05), no GitHub Action is pinned by hash (A-06), and the public documents describe features that do not exist, call the project unusable, and include an internal business memo (A-07 to A-09).

Counts: 0 critical, 9 high, 31 medium, 21 low.

Severity scale: **critical** = key or plaintext exposure to the server, or a break of a hard rule, exploitable now. **High** = fix before the public release. **Medium** = fix before or soon after the release, or document. **Low** = hardening and cleanup.

**Crypto and hard rules**
- Presets: `core/params/ckks_presets.json` and the packaged copy are byte-identical and a test enforces it; the server's preset table is generated from the same file. **Client**
