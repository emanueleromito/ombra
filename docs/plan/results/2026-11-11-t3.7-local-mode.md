## Bug found while running the e2e test

The local e2e test failed with EOFError during create. Root cause: /tmp (a tmpfs) was full of old
pytest dirs, so the child's own file write raised OSError (ENOSPC). `_serve_call` re-raised every
OSError, and the child's connection handler treated it as a closed socket and closed the
connection without a message. Fix: only EOFError and ConnectionError (a dead socket) are
re-raised; any other exception, OSError included, is sent to the client as an error frame carrying
the exception type name only. The e2e test also had stale filter assertions (the default probe
policy became "e_a" in T3.11); they now pass `probe="basic"`.
